## Question

[Animation format](../../base-direction/tickets/08-animation-format.md) ruled out copying SVC's frame and collision records directly. At what granularity is Guile translated: a converter that rewrites every SVC pose and box into KOF 2003 records, hand-authored records per action, or a mix? Where does the converter run and how is its output fed to the native build? Decide what is reusable for the next import and what stays manual.

_PT-BR: O [formato de animação](../../base-direction/tickets/08-animation-format.md) descartou copiar direto os registros de quadro e colisão do SVC. Em que granularidade o Guile é traduzido: um conversor que reescreve cada pose e caixa do SVC em registros do KOF 2003, registros escritos à mão por ação, ou uma mistura? Onde o conversor roda e como sua saída chega ao build nativo? Decidir o que se reaproveita na próxima importação e o que fica manual._

## Notes

- [How KOF 2003 turns a fighter ID into code, animations, graphics, palettes and sounds](01-fighter-id-to-data.md): collision is four 6-byte boxes inside each step of the per-fighter step scripts (file `$380000` directory), alongside velocity commands and sound codes; sprite frames sit in a separate per-fighter directory (file `$200000`) whose layout is not fully decoded, hence the blocker [How KOF 2003's sprite-frame records number their tiles](18-sprite-frame-tiles.md).
- [Inventory of Guile's SVC animations and assets for this slice](05-guile-svc-inventory.md): SVC records are three words (x offset, y offset, pose index) with no duration field; durations were measured.
- [How the native port's generator handles changed or added 68000 code and data](04-port-generator.md): data reads are live, but any change to the prepared `271-pd.bin` regenerates the C; rerunning `kof2003_decrypt` rewrites the prepared folder, so patching the prepared files and adding a step after preparation are both open.

_PT-BR: colisão são quatro caixas de 6 bytes dentro de cada passo dos scripts de passos do lutador, junto com velocidade e sons; os quadros de sprite ficam em outro diretório, de formato ainda não todo decodificado (daí o bloqueio pelo ticket 18). Os registros do SVC têm três palavras (x, y, índice de pose) e nenhuma duração. As leituras de dados são ao vivo, mas mudar o `271-pd.bin` preparado gera o C de novo; rodar o `kof2003_decrypt` outra vez reescreve a pasta preparada, então ficam em aberto modificar os arquivos preparados ou acrescentar um passo depois do preparo._

## Resolution

**English.** Decided by the owner on 2026-11-16.

- **Granularity: a full converter.** Every SVC pose span of Guile becomes one KOF 2003 step: duration, frame, offset, boxes rewritten into six bytes, velocity as command `$06`. Box kinds and the flag bytes `+$50`–`+$53`, which SVC does not state, are set by rule inside the converter. The push box (four boxes in action `$3FF`) is generated by the same rule.
- **Everything is recorded so bugs are easy to fix.** For every record the converter writes a log line with the SVC source (pose, span, box), the rule that produced each value and the value chosen. A per-record corrections file overrides the rule, so a wrong box kind or flag is fixed in that one record, not by changing the converter. The log and the corrections are plain text.
- **Where it runs: before preparation.** A converter tool generates a data file that is applied to the files before `271-pd.bin` is prepared and the C regenerated; the native build reads it as ordinary data, with no patch afterwards. This avoids the open question of adding a step after preparation.
- **Language: Python now, Rust only if it hurts.** The input is a few dozen poses and the output a few KB, so speed is not a concern, the repository's tools are already Python, and quick edit-and-run matters when fixing rules. Because the output is a text data file, the tool can be rewritten in Rust later by replacing one piece. Rust stays an option if the converter grows or becomes slow.
- **Reusable for the next import:** the converter, its rules and the log format. **Manual per import:** the corrections file.
- **Left to implementation:** the rule for box kinds and flags (the ticket 20 shortcut of copying Adelheid's flag values conflicts with "nothing from Adelheid" and must be replaced by a rule or measured values from KOF 2003), the attack-index tables of ticket 15, and where the prepared files are rewritten.

**Português (Brasil).** Decidido pelo dono em 16/11/2026.

- **Granularidade: conversor completo.** Cada trecho de pose do Guile no SVC vira um passo do KOF 2003: duração, quadro, deslocamento, caixas reescritas em seis bytes e velocidade como comando `$06`. O tipo de cada caixa e os bytes de flag `+$50`–`+$53`, que o SVC não informa, são definidos por regra dentro do conversor. A caixa de empurrão (quatro caixas na ação `$3FF`) sai da mesma regra.
- **Tudo fica registrado para facilitar a correção de bugs.** Para cada registro o conversor grava uma linha de log com a origem no SVC (pose, trecho, caixa), a regra que gerou cada valor e o valor escolhido. Um arquivo de correções por registro vence a regra, então um tipo de caixa ou flag errado é corrigido naquele registro, sem mexer no conversor. Log e correções são texto simples.
- **Onde roda: antes da preparação.** Uma ferramenta gera um arquivo de dados aplicado aos arquivos antes de preparar o `271-pd.bin` e regenerar o C; o build nativo lê como dado comum, sem remendo depois. Isso evita a questão em aberto de acrescentar um passo após a preparação.
- **Linguagem: Python agora, Rust só se doer.** A entrada são algumas dezenas de poses e a saída alguns KB, então velocidade não importa, as ferramentas do repositório já são Python e editar e rodar rápido ajuda ao corrigir regras. Como a saída é um arquivo de texto, dá para reescrever em Rust depois trocando uma peça só. Rust fica como opção se o conversor crescer ou ficar lento.
- **Reaproveitável no próximo import:** o conversor, suas regras e o formato do log. **Manual por import:** o arquivo de correções.
- **Fica para a implementação:** a regra de tipos de caixa e flags (o atalho do ticket 20 de copiar os valores da Adelheid conflita com "nada da Adelheid" e precisa virar regra ou valores medidos do KOF 2003), as tabelas de índice de ataque do ticket 15 e o ponto onde os arquivos preparados são reescritos.
